The problem

Every LLM call re-reads
your entire history. Every time.

A 200-message conversation is 50,000+ tokens. Without a memory system, that entire context is sent to the LLM on every single request — making long conversations slow, expensive, and eventually impossible when you hit the context window ceiling.

❌ Without this system
50,000

tokens per request

Re-reads everything, every time. $1.50 per request at GPT-4 pricing. 8–15 second latency. Hits context limit after ~200 messages. AI starts forgetting.
✅ With this system
2,000

tokens per request

Retrieves only what's relevant. $0.06 per request. Under 150ms latency. Unlimited conversation length. AI remembers forever — across sessions.
Architecture

Built in four phases.
Each one measurable.

The system is a layered ML infrastructure project — each phase adds a new capability on top of the previous, with benchmarks at every layer.

Phase 1 — Foundation
Importance Scoring + Vector Store
Every message gets scored 0–1 using semantic similarity, keyword signals, and recency decay. ChromaDB stores memories in three tiers: short-term RAM buffer → working memory → long-term vector store.
importance_scorer.py
memory_store.py
memory_types.py
Phase 2 — Compression
LLM Summarization + PCA + int8
Compressed 1500-token chunks → 200-token structured summaries via LLM. PCA reduces embedding dimensions 384→128. int8 quantization shrinks vector memory by 97%. 1M memories: 1.5 GB → 48 MB.
summarizer.py
embedding_compressor.py
hierarchical_memory.py
Phase 3 — Retrieval
BM25 + FAISS + Redis + FastAPI
BM25 keyword search + FAISS semantic search merged via Reciprocal Rank Fusion — 8–15% better precision than either alone. Redis cache serves 35% of queries in <5ms. FastAPI REST API + Docker deployment.
hybrid_retriever.py
cache.py
token_budget_optimizer.py
Phase 4 — Research
RL Policy + Knowledge Graph + Pruning
Q-learning agent learns STORE/COMPRESS/PROMOTE/DELETE from retrieval feedback. Knowledge graph tracks entities across sessions. Attention pruning removes low-value tokens before compression runs.
rl_memory_policy.py
knowledge_graph.py
attention_pruner.py

Hierarchical Semantic Memory Compression for Long-Context LLMs with Reinforcement Learning Memory Policy
Anish Mannem, University of Florida · 2026
We present a hierarchical memory compression system that reduces LLM context token usage by 78–86% while preserving 92%+ retrieval precision. Our system introduces importance-scored tier promotion, hybrid BM25+FAISS retrieval with RRF fusion, and a Q-learning memory policy trained on retrieval feedback — outperforming rule-based baselines across all metrics.
